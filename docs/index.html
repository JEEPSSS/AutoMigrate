TechPulse AutoMigrate

A SQL Server database for TechPulse, an authorised repair centre for phones, tablets, watches and audio wearables. It tracks every device from intake to warranty claim. One command wipes, rebuilds, seeds and queries the whole thing.

17 tables 45 service tickets · 70 work sessions 40 bills · 15 warranty claims 23/23 server checks passed · Microsoft SQL Server 2022 RTM 16.0.1000.6 · 2026-10-24

Run it

Python + pyodbc against the NTU lab server. Copy config.example.py to config.py first. The password is prompted for, never stored.

python run.py test

Check the connection to the server and team database.

python run.py all

Drop → create 17 tables → seed → create trigger.

python run.py demo

Walk through Q1–Q6: show the SQL, run it, show the results, wait for Enter.

python run.py export

Write every result and table to outputs/ for the report.

Careful: all drops every table in the configured database, not just TechPulse's.

Design changes since Lab 3

Applied from TA feedback and what the queries needed.

  1. Redundant client links removed. SERVICE_TICKET and WARRANTY_CLAIM no longer store Client_ID. The client is reached through DEVICE (and BILLING_STATEMENT → SERVICE_TICKET).
  2. GENERATES dropped. Each ticket has at most one bill, so BILLING_STATEMENT holds Service_Ticket_ID directly as a unique foreign key.
  3. IMEI_Serial_No on DEVICE. The real-world identifier, kept as a candidate key. Q6 lists it.
  4. Warranty_Claim_ID on SERVICE_TICKET. Marks warranty rework jobs, which the Q5 stock rule allows.
  5. REPAIR_PROCEDURE, not PROCEDURE. PROCEDURE is a reserved word in T-SQL.
Q110 rows

For each repair station, count how many repair job/procedure took less than 180 minutes to complete. Breakdown the count by Device Category (e.g., Smartphone, Tablet, Smartwatch, Audio Wearables).

WITH ProcTime AS (
    SELECT p.Procedure_ID, p.Service_Ticket_ID,
           SUM(ws.Billable_Time) AS Total_Minutes
    FROM REPAIR_PROCEDURE p
    JOIN WORK_SESSION ws    ON ws.Procedure_ID = p.Procedure_ID
    JOIN SERVICE_TICKET st  ON st.Service_Ticket_ID = p.Service_Ticket_ID
    WHERE st.Status IN ('Ready for Pickup', 'Completed')      -- finished jobs only
    GROUP BY p.Procedure_ID, p.Service_Ticket_ID
)
SELECT w.Workstation_ID, w.Workstation_Type, dt.Device_Category,
       COUNT(*) AS Procedures_Under_180_Min
FROM ProcTime pt
JOIN SERVICE_TICKET st ON st.Service_Ticket_ID = pt.Service_Ticket_ID
JOIN WORKSTATION w     ON w.Workstation_ID = st.Workstation_ID
JOIN DEVICE d          ON d.Device_ID = st.Device_ID
JOIN DEVICE_TYPE dt    ON dt.Model_ID = d.Model_ID
WHERE pt.Total_Minutes < 180
GROUP BY w.Workstation_ID, w.Workstation_Type, dt.Device_Category
ORDER BY w.Workstation_ID, dt.Device_Category;

How it works

The CTE sums each procedure's work-session minutes (γ Procedure_ID; SUM(Billable_Time)) and keeps only procedures on finished tickets (Ready for Pickup / Completed). A procedure counts as finished only when its ticket is done. The main query joins each procedure to its ticket's workstation and to the device's category (via DEVICE → DEVICE_TYPE), keeps procedures with total time < 180 minutes, and groups by workstation and category to count them. The Micro-Soldering Desk (3) does not appear because logic-board jobs in our data all ran 180 minutes or more.

Q25 rows

For each Device Category, list the total revenue generated across all completed work orders. Display the total revenue collected from Labor Fees (derived from technician work logs) and Spare Parts (derived from allocated parts at locked-in prices) separately.

WITH Completed AS (                     -- a bill exists only once all procedures are done
    SELECT st.Service_Ticket_ID, dt.Device_Category
    FROM SERVICE_TICKET st
    JOIN BILLING_STATEMENT b ON b.Service_Ticket_ID = st.Service_Ticket_ID
    JOIN DEVICE d            ON d.Device_ID = st.Device_ID
    JOIN DEVICE_TYPE dt      ON dt.Model_ID = d.Model_ID
),
Labour AS (
    SELECT p.Service_Ticket_ID,
           SUM(ws.Billable_Time / 60.0 * t.Standard_Hourly_Billing_Rate) AS Labour_Fee
    FROM REPAIR_PROCEDURE p
    JOIN WORK_SESSION ws ON ws.Procedure_ID = p.Procedure_ID
    JOIN TECHNICIAN t    ON t.Technician_ID = ws.Technician_ID
    GROUP BY p.Service_Ticket_ID
),
Parts AS (
    SELECT p.Service_Ticket_ID,
           SUM(pa.Quantity_Allocated * pa.Locked_Unit_Price) AS Parts_Fee
    FROM REPAIR_PROCEDURE p
    JOIN PART_ALLOCATION pa ON pa.Procedure_ID = p.Procedure_ID
    GROUP BY p.Service_Ticket_ID
)
SELECT c.Device_Category,
       COUNT(*)                                                    AS Completed_Work_Orders,
       CAST(SUM(COALESCE(l.Labour_Fee, 0)) AS DECIMAL(12,2))       AS Labour_Revenue,
       CAST(SUM(COALESCE(pr.Parts_Fee, 0)) AS DECIMAL(12,2))       AS Spare_Parts_Revenue,
       CAST(SUM(COALESCE(l.Labour_Fee, 0) + COALESCE(pr.Parts_Fee, 0)) AS DECIMAL(12,2)) AS Total_Revenue
FROM Completed c
LEFT JOIN Labour l ON l.Service_Ticket_ID = c.Service_Ticket_ID
LEFT JOIN Parts pr ON pr.Service_Ticket_ID = c.Service_Ticket_ID
GROUP BY c.Device_Category
ORDER BY Total_Revenue DESC;

How it works

Completed work orders are tickets that have a billing statement. Labour and parts are aggregated per ticket in two separate CTEs before joining. Joining work sessions and part allocations together would multiply rows: two sessions × two parts would double-count both. Labour = Σ(Billable_Time/60 × hourly rate). Parts = Σ(Quantity × Locked_Unit_Price), the price frozen at allocation, so later catalogue price changes do not alter revenue. The per-ticket totals are then grouped by device category.

Q37 rows

List all customers who have filed Warranty Claims for repair jobs executed by a technician whose specialization does not match the category of the serviced device (e.g., a technician specializing in "Display" repairing an "Headphone" on procedure related to "Audio"). For each affected customer, count how many total warranty claims they have filed, broken down by Device Manufacturer.

WITH MismatchTickets AS (
    SELECT DISTINCT p.Service_Ticket_ID
    FROM REPAIR_PROCEDURE p
    JOIN WORK_SESSION ws ON ws.Procedure_ID = p.Procedure_ID
    JOIN TECHNICIAN t    ON t.Technician_ID = ws.Technician_ID
    WHERE t.Primary_Specialisation <> p.Procedure_Type
),
AffectedCustomers AS (
    SELECT DISTINCT d.Client_ID
    FROM WARRANTY_CLAIM wc
    JOIN BILLING_STATEMENT b ON b.Bill_ID = wc.Bill_ID
    JOIN SERVICE_TICKET st   ON st.Service_Ticket_ID = b.Service_Ticket_ID
    JOIN DEVICE d            ON d.Device_ID = st.Device_ID
    WHERE st.Service_Ticket_ID IN (SELECT Service_Ticket_ID FROM MismatchTickets)
)
SELECT c.Client_ID, c.Name AS Customer_Name, dt.Manufacturer_Name,
       COUNT(wc.Claim_ID) AS Total_Warranty_Claims
FROM AffectedCustomers ac
JOIN CLIENT c            ON c.Client_ID = ac.Client_ID
JOIN DEVICE d            ON d.Client_ID = c.Client_ID
JOIN DEVICE_TYPE dt      ON dt.Model_ID = d.Model_ID
JOIN SERVICE_TICKET st   ON st.Device_ID = d.Device_ID
JOIN BILLING_STATEMENT b ON b.Service_Ticket_ID = st.Service_Ticket_ID
JOIN WARRANTY_CLAIM wc   ON wc.Bill_ID = b.Bill_ID
GROUP BY c.Client_ID, c.Name, dt.Manufacturer_Name
ORDER BY c.Client_ID, dt.Manufacturer_Name;

Q52 allowed · 1 blocked

When a spare component's available stock drops below 20% of its minimum reorder threshold, remaining units can only be allocated to work orders for Corporate Clients or Warranty Claims. Prepare your SQL queries and data checks to simulate both a Success scenario (part allocation allowed for a corporate/warranty job) and a Fail scenario (part allocation blocked for a standard retail job).

Corporate job · ticket 43ALLOWEDstock 3 → 2
Warranty rework · ticket 45ALLOWEDstock 2 → 1
Retail job · ticket 44BLOCKEDRAISERROR + ROLLBACK

Trigger

CREATE OR ALTER TRIGGER trg_PartAllocation_Guard
ON PART_ALLOCATION
INSTEAD OF INSERT
AS
BEGIN
    SET NOCOUNT ON;

    -- Rule check: critically low part requested by a job that is neither corporate nor warranty
    IF EXISTS (
        SELECT 1
        FROM inserted i
        JOIN PART p             ON p.Part_Code = i.Part_Code
        JOIN REPAIR_PROCEDURE rp ON rp.Procedure_ID = i.Procedure_ID
        JOIN SERVICE_TICKET st  ON st.Service_Ticket_ID = rp.Service_Ticket_ID
        JOIN DEVICE d           ON d.Device_ID = st.Device_ID
        JOIN CLIENT c           ON c.Client_ID = d.Client_ID
        WHERE p.Current_Quantity < 0.2 * p.Minimum_Reorder_Quantity
          AND c.Type <> 'Corporate'
          AND st.Warranty_Claim_ID IS NULL
    )
    BEGIN
        RAISERROR('ALLOCATION BLOCKED: stock is below 20%% of the reorder threshold. Remaining units are reserved for Corporate or Warranty jobs.', 16, 1);
        ROLLBACK TRANSACTION;
        RETURN;
    END

    -- Basic stock check
    IF EXISTS (SELECT 1 FROM inserted i JOIN PART p ON p.Part_Code = i.Part_Code
               WHERE i.Quantity_Allocated > p.Current_Quantity)
    BEGIN
        RAISERROR('ALLOCATION BLOCKED: insufficient stock on hand.', 16, 1);
        ROLLBACK TRANSACTION;
        RETURN;
    END

    -- Allowed: insert with the price locked in from the catalogue right now
    INSERT INTO PART_ALLOCATION (Allocated_ID, Procedure_ID, Quantity_Allocated,
                                 Locked_Unit_Price, Allocated_Time, Part_Code)
    SELECT i.Allocated_ID, i.Procedure_ID, i.Quantity_Allocated,
           p.Selling_Price, COALESCE(i.Allocated_Time, GETDATE()), i.Part_Code
    FROM inserted i
    JOIN PART p ON p.Part_Code = i.Part_Code;

    -- Deduct stock
    UPDATE p
    SET p.Current_Quantity = p.Current_Quantity - x.Qty
    FROM PART p
    JOIN (SELECT Part_Code, SUM(Quantity_Allocated) AS Qty
          FROM inserted GROUP BY Part_Code) x ON x.Part_Code = p.Part_Code;

    PRINT 'ALLOCATION ALLOWED: part allocated and stock deducted.';
END;

How it works

An INSTEAD OF INSERT trigger on PART_ALLOCATION enforces the rule. For each new allocation it checks whether the part's Current_Quantity < 20% of Minimum_Reorder_Quantity. If so, it blocks the insert (RAISERROR + ROLLBACK) unless the client is Corporate or the ticket is a warranty job (Warranty_Claim_ID not NULL). Allowed rows are inserted with Locked_Unit_Price copied from PART.Selling_Price at that moment, which also enforces the price-lock rule, and stock is deducted. In the demo, BAT-IP15 has 3 units (threshold 20, so the restricted level is below 4). The Northwind (corporate) and Hannah Goh (warranty rework) allocations succeed and stock drops 3 → 1. Sophie Ong's retail allocation is rejected with an error.

Q62 rows

Identify any customer (individual or corporate) who has submitted more than three separate work orders within the same calendar month for devices belonging to the same Device Category. List the customer's name, email, the device category, the month/year, and the IMEI/Serial Numbers of all associated devices.

WITH TicketInfo AS (
    SELECT d.Client_ID, dt.Device_Category, d.IMEI_Serial_No,
           YEAR(st.Date_Received)  AS Yr,
           MONTH(st.Date_Received) AS Mth
    FROM SERVICE_TICKET st
    JOIN DEVICE d       ON d.Device_ID = st.Device_ID
    JOIN DEVICE_TYPE dt ON dt.Model_ID = d.Model_ID
)
SELECT c.Name AS Customer_Name, c.Email, ti.Device_Category,
       CONCAT(RIGHT(CONCAT('0', ti.Mth), 2), '/', ti.Yr) AS Month_Year,
       COUNT(*) AS Work_Orders,
       STRING_AGG(ti.IMEI_Serial_No, ', ') AS IMEI_Serial_Numbers
FROM TicketInfo ti
JOIN CLIENT c ON c.Client_ID = ti.Client_ID
GROUP BY c.Client_ID, c.Name, c.Email, ti.Device_Category, ti.Yr, ti.Mth
HAVING COUNT(*) > 3
ORDER BY c.Name, ti.Yr, ti.Mth;

P1. Technician(s) with the most billable hours; retain ties.
WITH Hours AS (
    SELECT t.Technician_ID, t.Name,
           SUM(ws.Billable_Time) AS Billable_Minutes
    FROM TECHNICIAN t
    JOIN WORK_SESSION ws ON ws.Technician_ID = t.Technician_ID
    GROUP BY t.Technician_ID, t.Name
)
SELECT TOP (1) WITH TIES Technician_ID, Name,
       CAST(Billable_Minutes / 60.0 AS DECIMAL(10,2)) AS Billable_Hours
FROM Hours
ORDER BY Billable_Minutes DESC;

P2. Recorded bill balances for unpaid/partial bills, grouped by client.
SELECT c.Client_ID, c.Name AS Client_Name,
       COUNT(*) AS Unsettled_Bills,
       SUM(b.Balance_Due) AS Recorded_Bill_Balance
FROM BILLING_STATEMENT b
JOIN SERVICE_TICKET st ON st.Service_Ticket_ID = b.Service_Ticket_ID
JOIN DEVICE d ON d.Device_ID = st.Device_ID
JOIN CLIENT c ON c.Client_ID = d.Client_ID
WHERE b.Payment_Status IN ('Unpaid', 'Partial')
GROUP BY c.Client_ID, c.Name
ORDER BY Recorded_Bill_Balance DESC, c.Client_ID;

P3. Parts at/below reorder level with no pending or shipped purchase order.
SELECT p.Part_Code, p.Item_Description, p.Current_Quantity,
       p.Minimum_Reorder_Quantity
FROM PART p
WHERE p.Current_Quantity <= p.Minimum_Reorder_Quantity
  AND NOT EXISTS (
      SELECT 1
      FROM RESTOCK_REQUEST rr
      JOIN CREATES cr ON cr.Req_ID = rr.Req_ID
      JOIN PURCHASE_ORDER po ON po.Order_ID = cr.Order_ID
      WHERE rr.Part_Code = p.Part_Code
        AND po.Order_Status IN ('Pending', 'Shipped')
  )
ORDER BY p.Part_Code;

P4. Mean calendar-day boundaries from intake to billing, per category.
SELECT dt.Device_Category, COUNT(*) AS Billed_Orders,
       CAST(AVG(CAST(DATEDIFF(DAY, st.Date_Received, b.Billing_Date)
                     AS DECIMAL(10,2))) AS DECIMAL(10,2)) AS Average_Days
FROM BILLING_STATEMENT b
JOIN SERVICE_TICKET st ON st.Service_Ticket_ID = b.Service_Ticket_ID
JOIN DEVICE d ON d.Device_ID = st.Device_ID
JOIN DEVICE_TYPE dt ON dt.Model_ID = d.Model_ID
GROUP BY dt.Device_Category
ORDER BY Average_Days DESC, dt.Device_Category;

P5. Vendor(s) with the largest total purchase-order value; retain ties.
SELECT TOP (1) WITH TIES v.Vendor_ID, v.Name AS Vendor_Name,
       COUNT(*) AS Purchase_Orders,

JOIN PURCHASE_ORDER po ON po.Vendor_ID = v.Vendor_ID

P7. Billed revenue by billing month in 2026, before tax and discounts.
SELECT CONVERT(CHAR(7), b.Billing_Date, 120) AS Billing_Month,
       COUNT(*) AS Bills,
       SUM(b.Total_Labour_Charges) AS Labour_Revenue,
       SUM(b.Total_Component_Costs) AS Parts_Revenue,
       SUM(b.Total_Labour_Charges + b.Total_Component_Costs) AS Total_Revenue
FROM BILLING_STATEMENT b
WHERE b.Billing_Date >= '20260101' AND b.Billing_Date < '20270101'
GROUP BY CONVERT(CHAR(7), b.Billing_Date, 120)
ORDER BY Billing_Month;

P8. Approved warranty claims as a percentage of all submitted claims.
SELECT dt.Manufacturer_Name, COUNT(*) AS Total_Claims,
       SUM(CASE WHEN wc.Review_Status = 'Approved' THEN 1 ELSE 0 END) AS Approved,
       CAST(100.0 * SUM(CASE WHEN wc.Review_Status = 'Approved' THEN 1 ELSE 0 END)
            / COUNT(*) AS DECIMAL(6,2)) AS Approval_Rate_Percent
FROM WARRANTY_CLAIM wc
JOIN BILLING_STATEMENT b ON b.Bill_ID = wc.Bill_ID
JOIN SERVICE_TICKET st ON st.Service_Ticket_ID = b.Service_Ticket_ID
JOIN DEVICE d ON d.Device_ID = st.Device_ID
JOIN DEVICE_TYPE dt ON dt.Model_ID = d.Model_ID
GROUP BY dt.Manufacturer_Name
ORDER BY Approval_Rate_Percent DESC, dt.Manufacturer_Name;

Technicians with sessions who never worked outside their specialisation.
SELECT t.Technician_ID, t.Name, t.Primary_Specialisation,
       COUNT(*) AS Sessions
FROM TECHNICIAN t
JOIN WORK_SESSION ws ON ws.Technician_ID = t.Technician_ID
JOIN REPAIR_PROCEDURE rp ON rp.Procedure_ID = ws.Procedure_ID
GROUP BY t.Technician_ID, t.Name, t.Primary_Specialisation
HAVING SUM(CASE WHEN t.Primary_Specialisation <> rp.Procedure_Type
                THEN 1 ELSE 0 END) = 0
ORDER BY t.Technician_ID;

Busiest workstation by total assigned tickets; retain tied leaders.
SELECT TOP (1) WITH TIES w.Workstation_ID, w.Workstation_Type,
       COUNT(st.Service_Ticket_ID) AS Tickets
FROM WORKSTATION w
LEFT JOIN SERVICE_TICKET st ON st.Workstation_ID = w.Workstation_ID
GROUP BY w.Workstation_ID, w.Workstation_Type
ORDER BY COUNT(st.Service_Ticket_ID) DESC;
